# Data Model: CodeToDocs

**Branch**: `001-local-cli-tool` | **Date**: 2026-02-09

## Entities

### 1. Configuration (`config.yaml`)

The runtime configuration loaded by prompt commands.

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `output_dir` | string | No | `docs/` | Directory where generated docs are written |
| `target_branch` | string | No | `main` | Branch to diff against for incremental updates |
| `components` | Component[] | No | (entire repo) | List of component definitions |
| `documents` | CustomDocument[] | No | (none) | Additional document types beyond defaults |

**Validation rules**:
- `output_dir` must be a relative path (no leading `/`)
- `target_branch` must be a valid Git ref
- `components[].paths` entries must not overlap across components (warn if they do)

### 2. Component

A logical unit of the codebase that gets its own documentation set.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Identifier used in output filenames (e.g., `frontend`, `backend`) |
| `paths` | string[] | Yes | Directories/files belonging to this component |
| `description` | string | No | Human-readable description for context |

**State transitions**: None — components are static config.

**Implicit component**: When `components` is not defined, the entire repository is treated as a single component with `name` = repository directory name.

**Uncategorized component**: When `components` is defined but files don't match any path, those files are grouped into an implicit `"uncategorized"` component.

### 3. Custom Document

A user-defined document type beyond the three defaults.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Document type identifier (e.g., `runbook`) |
| `template` | string | Yes | Path to template file relative to repo root |
| `output` | string | Yes | Output path pattern with `{component}` placeholder |
| `audience` | string | No | Description of the target audience |

### 4. Documentation Artifact

A generated output file. Not persisted as a data model — exists as a file on disk.

| Attribute | Description |
|-----------|-------------|
| Component name | Which component this doc describes |
| Doc type | `technical`, `product`, `ai_context`, or custom name |
| File path | Computed from `output_dir` + doc type + component name |
| Header marker | `<!-- CodeToDocs | Component: {name} | Generated: {timestamp} -->` |
| Content | Generated by agent following the template structure |

**Three default types per component**:

| Type | Template | Output Path | Format |
|------|----------|-------------|--------|
| Technical | `.codetodocs/templates/technical_doc.md` | `{output_dir}/technical/{component}.md` | Markdown |
| Product | `.codetodocs/templates/product_doc.md` | `{output_dir}/product/{component}.md` | Markdown |
| AI Context | `.codetodocs/templates/ai_context.json` | `{output_dir}/ai/{component}.json` | JSON |

### 5. Template

A structural guide defining expected output format. User-customizable.

| Template File | Sections/Fields |
|---------------|-----------------|
| `technical_doc.md` | Purpose, Architecture, Setup/Installation, Running, Configuration, Key APIs, Edge Cases, Dependencies |
| `product_doc.md` | Purpose, Features, Business Rules, User Impact, Configuration/Policies |
| `ai_context.json` | `_codetodocs`, `component`, `modules`, `api`, `types`, `configuration`, `dependencies`, `metrics` |

### 6. Ignore Rules

Not a persisted entity — computed at runtime.

| Source | Location | Behavior |
|--------|----------|----------|
| `.gitignore` | Repo root (+ nested) | Always respected |
| `.codetodocsignore` | Repo root | Optional, additive exclusions |

Invalid patterns in `.codetodocsignore` are reported and skipped.

### 7. Installer Asset Manifest

The set of files the bootstrap installer copies into a target repo.

| Source (in package) | Target (in user repo) |
|---------------------|-----------------------|
| `assets/prompts/codetodocs.init.prompt.md` | `.github/prompts/codetodocs.init.prompt.md` |
| `assets/prompts/codetodocs.run.prompt.md` | `.github/prompts/codetodocs.run.prompt.md` |
| `assets/prompts/codetodocs.status.prompt.md` | `.github/prompts/codetodocs.status.prompt.md` |
| `assets/templates/technical_doc.md` | `.codetodocs/templates/technical_doc.md` |
| `assets/templates/product_doc.md` | `.codetodocs/templates/product_doc.md` |
| `assets/templates/ai_context.json` | `.codetodocs/templates/ai_context.json` |

**Idempotency**: Existing files are never overwritten; skipped files are reported.

## Entity Relationships

```
Configuration 1──* Component
Configuration 1──* CustomDocument
Component 1──* DocumentationArtifact
CustomDocument 1──1 Template
DocumentationArtifact *──1 Template
```

## State Diagram: Documentation Lifecycle

```
[Not Initialized] --/codetodocs.init--> [Initialized (no docs)]
[Initialized (no docs)] --/codetodocs.run--> [Documented]
[Documented] --source changes--> [Potentially Stale]
[Potentially Stale] --/codetodocs.run--> [Documented]
[Documented] --component deleted--> [Orphaned (flagged)]
```
